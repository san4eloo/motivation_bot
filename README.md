# Personal Schedule Bot 4.0

Личный Telegram-бот: постоянное расписание, личные задачи, фактический учёт времени и недельная статистика.

## Что нового в v4

- PostgreSQL вместо `tasks.json`.
- `/tasks` показывает inline-кнопки — ID задач вводить не нужно.
- После кнопки **✅ Выполнено** можно:
  - одним нажатием засчитать время по плану;
  - ввести фактическое время, например `16:10 17:35`.
- В `/stats` учитываются **только выполненные задачи и фактическое время**.
- Категории: `programming`, `reading`, `work`, `study`, `other`.
- `/stats` сравнивает текущую неделю с прошлой.
- Каждое воскресенье в 16:00 МСК статистика приходит автоматически.
- За 15 минут до личной задачи приходит напоминание.
- В 07:00: доброе утро + цитата + расписание сегодня.
- В 22:00: спокойной ночи + цитата + расписание на завтра.

## Команды

```text

/add programming 16:00 18:00

/add reading Чистый код 21:00 22:00
```

### `/tasks`

Команда выводит задачи с кнопками. У запланированной задачи есть кнопка **✅ Название задачи** и кнопка отмены.

После **✅** бот предложит:

- **✅ По плану** — плановое время станет фактическим;
- **✍️ Ввести фактическое время** — после этого отправь, например `16:10 17:35`.

Внутренний UUID хранится в PostgreSQL и callback-кнопке, пользователю его запоминать не нужно.

## Локальный запуск

### 1. PostgreSQL

Самый простой вариант, если установлен Docker Desktop:

```bash
docker compose up -d postgres
```

### 2. `.env`

Создай `.env` рядом с `package.json`:

```env
BOT_TOKEN=токен_от_BotFather
CHAT_ID=твой_chat_id
TIMEZONE=Europe/Moscow
DATABASE_URL=postgresql://schedule_bot:schedule_bot@localhost:5432/schedule_bot
DATABASE_SSL=false
TASK_REMINDER_MINUTES=15
```

### 3. Установка и запуск

```bash
npm install
npm run dev
```

При первом запуске таблица `tasks` и индексы создаются автоматически.

Production:

```bash
npm run build
npm start
```

## Как считается статистика

Постоянное расписание ВУЗа и спорта хранится в `src/schedule/weeklySchedule.ts`.

В личную статистику попадают только задачи со статусом `completed`. Используется `actual_start` / `actual_end`, а не плановое время.

Категории `programming`, `reading`, `work`, `study` считаются полезным свободным временем. `other` отображается отдельно, но не повышает процент эффективности.

Эффективность:

```text
полезное фактическое время / доступное свободное время × 100%
```

Доступное свободное время = 07:00–22:00 за неделю минус ВУЗ и спорт.

## Хостинг

Проект рассчитан на постоянно работающий Node.js-процесс и PostgreSQL. Для деплоя нужно задать те же environment variables. Если платформа выдаёт PostgreSQL через `DATABASE_URL`, укажи её в окружении бота.
